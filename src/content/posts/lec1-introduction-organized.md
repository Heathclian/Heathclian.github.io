> 一句话主线：**密码学的安全性不靠"藏住算法"，而是把全部赌注押在密钥上；现代密码学的贡献，是把"安全"变成一道可以证明的数学命题（定义 + 假设 + 归约）。**

## 1. 密码学与通信模型

**Cryptography** 源自希腊文，意为 *hidden to write*（隐藏地书写）。

| 角色 | 含义 |
| --- | --- |
| Alice (A) | 发送方 |
| Bob (B) | 接收方 |
| Eve (E) | 窃听者，即 adversary（敌手） |
| O | 可信第三方，负责分发密钥 |

A 与 B 之间借助密钥（secret key）通信，目标是让 Eve 无法获知通信内容。

![Alice 与 Bob 的通信模型](./lec1/Alice_and_Bob.png)

## 2. 加密方案的语法（Syntax）

$$Gen(\cdot)\rightarrow sk,\qquad Enc(sk,m)\rightarrow c,\qquad Dec(sk,c)\rightarrow m$$

三个算法对随机性的要求并不相同：

| 算法 | 类型 | 原因 |
| --- | --- | --- |
| $Gen$ | 随机算法（Randomized） | 需要产生随机数、导出密钥并分发给 A、B |
| $Enc$ | 随机或确定均可 | DES、AES 是确定性的；一些公钥加密用非确定性算法 |
| $Dec$ | 确定性算法（Deterministic） | 解出的明文必须唯一确定，否则不是我们想要的结果 |

> 纯理论层面可以不把 $Dec$ 当作确定性算法来要求；在主流定义与工程实践中它是确定性算法。

## 3. 正确性（Correctness）

- $M$：message space，明文空间——明文可能出现的范围；
- $K$：secret key space，密钥空间——$Gen$ 可能产生的密钥的集合。

$$Correctness:=\forall m\in M,\ Gen\rightarrow sk,\ \Pr\big[Dec(sk,Enc(sk,m))=m\big]=1$$

两点补充：

1. 实际定义中可以放松到 $1-negl(n)$，即允许以可忽略概率解密失败；
2. "$Gen\rightarrow sk$" 与"从 $K$ 中取 $sk$"严格来说**并不等价**：$Gen$ 生成的密钥分布未必均匀，而从 $K$ 中随机取样的 $sk$ 熵最大。

:::note
**为什么叫"空间"而不是"集合"？** 在没有定义额外运算（加法、内积）时，明文与密钥的全体确实只是一个**裸集**。但密码学沿用了概率论"样本空间"的习惯，并且总会在其上附加**概率分布**——一旦集合被赋予 $\sigma$-代数与概率测度，它就真的成了**概率空间**；若再把密钥看作系统的内部状态，还会引出**状态空间**的视角。所以"空间"一词暗示了那些没明说、却处处在用的结构。
:::

## 4. 安全性：Kerckhoffs 原则

**问题**：Eve 能否知道 $(Gen,Enc,Dec)$？安全性是否依赖于敌手不知道这三个算法？

假设"安全性依赖算法保密"，立即会遇到两个问题：

1. 算法最终会泄露；
2. 保密成本高。

而算法之所以有意义，前提是它可以被"应用"；一旦应用，就必然被观察、被逆向。于是这样的算法无法真正被使用，与前提矛盾，**假设不成立**。

> **Kerckhoffs 原则（1884）**：密码的安全性仅仅依赖于密钥是安全的。

:::tip
安全模型主要取决于两方面：**敌手拥有什么能力** + **要达到什么样的安全目标**。这两件事说清楚了，"安全"才有意义。
:::

## 5. 古典密码：从凯撒到频率分析

古典时期的标准是"一套密码没被攻破就是安全的"——没有定义，也就没有说服力。

| 方案 | 密钥 | 为什么会被破 |
| --- | --- | --- |
| 凯撒加密 | 固定为 3 | 密钥写死，$Gen$ 是确定性算法，**严格来说它不是密码算法** |
| 位移加密（abcd→cdab） | $sk=2$，$\lvert K\rvert=26$ | 密钥空间太小可枚举；明文仍是字母，很容易看出是否"有意义" |
| 置换加密（abcd→cadb） | $sk$ 是置换表，$\lvert K\rvert=26!$ | 密钥空间已经很大，但英文**字母使用频率**仍会泄露 $sk$ |

数学视角：位移加密对应**轮换（循环置换）群**；置换加密对应对称群 $S_{26}$，其中每个元素都可写成一堆轮换的乘积。

## 6. 可证明安全（Provable Security）

这是现代密码学的基础：用"proof"为安全提供 evidence。

$$\textbf{安全定义} + \textbf{数学假设} + \textbf{归约证明} \Rightarrow \textbf{可证明安全}$$

- **数学假设**：困难的数学问题，例如大整数分解、$P\neq NP$；
- **归约（Reduction）**：若存在敌手 $A$ 打破了方案 $\pi$ 的安全性，就对 $A$ 做一层"包装" $B=R^A$，使 $B$ 成为解决该数学问题的算法。于是：**数学问题不容易解 $\Rightarrow$ 基于它的加密方案是安全的**。

密码的基石是数学困难问题，归约的作用就是把密码方案与困难问题绑定在一起。

![Provable Security 的三段式](./lec1/Provable_Security.png)

:::caution[现实提醒]
归约并不总是"稳固"的。现实中常见的破法，恰恰是**攻击归约本身**（证明逻辑有洞），或直接攻击数学难题——例如 Shor 算法在量子计算机上运行即可破解 RSA 与椭圆曲线加密。
:::

## 7. 延伸：从"可证明安全"到"可证明的实现"

现代密码学最重要的启示是范式本身：**安全定义 + 假设 $\Rightarrow$ 证明**。把它迁移到代码与系统层面：

$$\textbf{安全规范} + \textbf{执行模型假设} + \textbf{程序正确性证明} \Rightarrow \textbf{可证明安全的实现}$$

- **代码级**：seL4（Isabelle/HOL 证明微内核 C 代码）、CompCert（Coq 验证编译器）、HACL\*/EverCrypt（F\* 验证密码库）、VST、Dafny；
- **协议级**：Tamarin、ProVerif、EasyCrypt / CryptoVerif；
- **组合证明**：Hoare 逻辑、分离逻辑、Rely-Guarantee、信息流类型系统——模块各自满足规范且接口条件成立，即可组合出全局规范（如 Ironclad）。

现实挑战同样明确：业务层面的"安全"难以精确形式化；证明只在模型假设内成立（Meltdown/Spectre 就打破了 CPU 隔离假设）；端到端证明的人力成本仍然很高。

## 8. 附：安全多方计算（MPC）

通过一些计算手段，保证多方各自输入的隐私不被泄露。参与者分为**诚实参与者**（输入的一定是实际情况）与**不诚实参与者**（输入的和实际情况不符）。

## 9. 小结

- 安全性**只押在密钥上**（Kerckhoffs），算法公开是常态；
- 谈安全性之前，先要说清方案的**语法**（$Gen/Enc/Dec$）与**正确性**；
- 古典密码的失败在于缺少**定义**，现代密码学的成功在于"定义 + 假设 + 归约"；
- 密码原语的基石是数学困难问题，安全性通过归约与之绑定。
